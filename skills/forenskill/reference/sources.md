# Sources and Standards Referenced

This procedure's content is drawn from, and should remain consistent with,
the following published standards and technical references. Where a phase
file and a cited source conflict, the published source governs.

- **NIST SP 800-86**, "Guide to Integrating Forensic Techniques into
  Incident Response" — overall collection / examination / analysis /
  reporting process framework.
- **NIST Computer Forensic Tool Testing Program (CFTT)** — tool validation
  and dual-tool verification guidance (Phase 2).
- **SWGDE** "Best Practices for Computer Forensic Acquisitions," "Best
  Practices for Computer Forensic Examinations," and "Best Practices for
  Digital Evidence Collection" — acquisition, examination, and
  chain-of-custody documentation practices (Phases 0–2).
- **ACPO** (Association of Chief Police Officers) "Good Practice Guide for
  Digital Evidence" — the four core principles for handling digital
  evidence (Phase 0 and throughout).
- **ISO/IEC 27037:2012** — identification, collection, acquisition, and
  preservation of digital evidence.
- **RFC 3227**, "Guidelines for Evidence Collection and Archiving" —
  order-of-volatility principle for live/volatile evidence (Phases 0, 8).
- **Microsoft and Apple platform documentation**, and established DFIR
  practitioner/vendor technical references (e.g. SANS DFIR courseware and
  posters, and widely-used open-source/commercial forensic tool
  documentation), for OS-specific artifact locations and behavior
  (Phases 7, 9, 10, 11). Artifact behavior can change across OS versions —
  confirm against the specific build under examination where a finding is
  central to the case.
